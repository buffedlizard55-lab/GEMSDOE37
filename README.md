# GEMSDOE37 — GEMS Prize research and submission system

> **Standing instruction: read this README and [`docs/PROJECT_CHARTER.md`](docs/PROJECT_CHARTER.md) before every work session.** The charter keeps the original goals, scientific constraints, and evidence rules in one place.

## Mission

Build an auditable, reproducible system for the DOE GEMS Prize challenge: identify previously unmapped geologic faults associated with geothermal resources, test each new method with spatially blocked validation, and produce a competition-format GeoTIFF only when the data and validation gates pass. The system must keep a current, source-linked public-leaderboard snapshot and make an eligible submission obvious and simple to download.

## Core values

- **Maximize P(Win)**: use limited weekly submissions for candidates that have beaten the current spatial-holdout best; do not submit exploratory ideas as lottery tickets.
- **Own the Outcome**: record failures and irregularities, correct defects, and distinguish measured facts from hypotheses and team-reported claims.

## Non-negotiable research and submission rules

1. **No copied entry.** The deliverable, when eligible, must be generated by this repository's independently implemented method and a recorded input-data manifest. Prior GEMSDOE artifacts may be examined as educational baselines only; they must not be repackaged as this repository's prediction.
2. **No fabricated results.** Public-leaderboard values, official rules, source data, and team-reported results must be labelled by evidence class and date. No estimated or simulated score may be called an organizer score.
3. **Holdout gate.** Register 3–5 novel, physically grounded hypotheses; compare the leading hypothesis against the current holdout-best baseline on preregistered spatial blocks, at matched prediction budget. A candidate that has not beaten that baseline is **not slot-eligible**.
4. **Topological persistence.** Where used, report the scalar-field filtration, births/deaths, persistence lifetime, smoothing-scale survival, matching rule, and perturbation bound. The stability theorem applies to persistence diagrams under a stated function-norm bound; it does **not** prove a geological fault exists, and a heuristic match across Gaussian scales is not itself a multiparameter-persistence theorem.
5. **Valid GeoTIFF.** Check the organizer template's CRS, dimensions, affine transform, resolution, single-band float32 type, and finite prediction range `[0, 1]` by reopening the written file. Never let nodata sentinels or infinities leak into values inspected by the portal.
6. **Visible submission workflow.** The site landing page must put the eligible `.tif` download, unique submission name, short DrivenData note, evidence status, and a clear upload guide at the top. If no candidate passes the gates, show **not submission-ready** rather than a misleading download button.
7. **Official-source audit.** Prefer DOE/NLR, USGS, DrivenData competition materials, and documented open research. Record the source URL, access date, specific claim supported, license where relevant, and any access/provenance limitation.
8. **Three review passes.** Implement and test; review/fix bugs and assumptions; compare the final work against this charter. Keep a short pass log in `research/`.

## Repository workflow

```bash
python -m pip install -e '.[test]'
pytest -q
bash scripts/download_competition_data.sh   # user-provided mirrors only; not official-source authentication
bash scripts/fetch_educational_baseline.sh  # evaluation-only historical raster; never use it as candidate pixels
python scripts/prepare_data.py
python scripts/build_candidate.py
python scripts/validate_candidate.py        # evaluate; does not write a submission TIFF
python scripts/validate_candidate.py --publish  # writes only if both fixed promotion gates pass
```

Competition data and derived intermediate arrays are ignored by Git. Read the scripts' provenance notices before running them; mirror format checks do not authenticate organizer provenance. The static site is in `docs/`; because this repository's current Pages source is `main` at `/` and the API denied a source-path change, the root `index.html` redirects into `docs/`. Allow the repository Actions token to create pull requests for the scheduled leaderboard feed. The refresh job proposes changed snapshots on the fixed session branch for review rather than silently changing the published site. DTI parity against the organizer's worked example and all raster evaluations remain pending until verified inputs are available.
