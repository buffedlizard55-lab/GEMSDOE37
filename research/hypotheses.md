# Ranked geological hypotheses and holdout plan

**Register date:** 2026-10-05, before any GEMSDOE37 competition-raster evaluation. **Status:** four distinct candidates are recorded below; only H1 has implementation code in this checkout, and none has a GEMSDOE37 raster result. This is not a claim of global novelty. Rank and expected DTI are qualitative planning judgments; there is no defensible numeric gain estimate without the authorized rasters and a matched holdout.

## Prior-work audit and novelty boundary

The sibling repositories and their reports substantially narrow what can honestly be called new:

- [GEMSDOE35 H35-06 PR #6](https://github.com/buffedlizard55-lab/GEMSDOE35/pull/6) implements multiscale DEM scarp curvature/slope-break detection and reports an owner-side 5/6-tile proxy gain. It is **not** an organizer score. GEMSDOE35 also registers tilt-angle edges (H35-07), geodetic dilation/shear (H35-08), gravity–magnetic Hessian/cross-gradient fusion (H35-09), and GeoDAWN radiometric ratios (H35-10). Do not relabel those families as new.
- [GEMSDOE30's hypothesis register](https://buffedlizard55-lab.github.io/GEMSDOE30/docs/hypotheses.md) already proposed matched-filter LiDAR scarps (H31-02), drainage offsets/knickpoints (H31-03), and K–Th–U ratios (H31-04); it also reports prior ablations. Those directions are excluded from this shortlist rather than presented as first discoveries.
- [GEMSDOE36's main repository](https://github.com/buffedlizard55-lab/GEMSDOE36) contains owner-side Anderson/PINN, gravity–magnetic, geothermal, and off-catalogue inventory experiments (PRs [#4](https://github.com/buffedlizard55-lab/GEMSDOE36/pull/4) and [#5](https://github.com/buffedlizard55-lab/GEMSDOE36/pull/5)). The reported validation uses owner-mirror data and a different proxy; it is not organizer-confirmed.
- H1 is **algorithmically distinct only in a narrow, checkable sense**: explicit H0 births/deaths for each fixed response field, followed by heuristic peak matching across Gaussian scales. Earlier work includes multiscale scarp transforms, curvature, and other ridge operations. No claim is made that persistence, multiscale geomorphology, or this combination is globally unprecedented.

### Ranking rationale

H1 ranks first because it uses the competition's physical layers and adds an explicit, auditable threshold-persistence test without requiring external archive alignment. H2 ranks second because acquisition-artifact rejection could improve precision, but its raw-data cost and spatial coverage are substantial unknowns. H3 and H4 add genuinely different observables, but measure only active/deforming or seismic subsets and have severe completeness risks. All expected DTI effects are qualitative; inventing numerical priors would imply calibration that does not exist.

## Scoring, holdout, and promotion protocol

- DrivenData staff clarify that **only exact provided known-fault pixels are masked**; there is no surrounding catalogue-distance buffer. New-fault pixels may lie within 300 m of a known trace and include corrections/continuations/splays. See the [scoring clarification](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4) and [definition of new fault](https://community.drivendata.org/t/where-do-you-draw-the-line/11536/2).
- The public metric pools all public-subset pixels into one DTI; the final evaluation is re-run over the full GeoDAWN area. The local protocol must therefore pool TP/FP/FN over the spatial blocks before calculating its summary DTI, not average per-block scores. See [leaderboard aggregation clarification](https://community.drivendata.org/t/leaderboard-aggregation-pooled-over-public-test-pixels-or-mean-of-per-chunk-scores/11550/2).
- The repository's four-quadrant spatial holdout uses a 300 m inner guard to reduce cross-boundary score-kernel leakage. That is **our validation design**, not the organizer's mask. It also excludes new-fault truth close to a visible fault and therefore cannot validate corrections/splays near known traces.
- The catalog raster provides only a **catalogue pseudo-holdout**: withholding mapped known faults tests transfer to other mapped faults, not discovery of hidden expert-only geometry. The historical H33-2-B2 static raster is not a valid fold comparator because its two-pixel pruning was made with the full catalogue, including held-out labels.
- Before a weekly slot, H1 must beat the same-budget single-scale control and a separately registered, hash-pinned **current local holdout-best report** on identical raw-input hashes and scoring protocol; it must pass the registered pooled-DTI and fold-stability margins; then the independently written TIFF must pass the template/range/mask validator. The current-best registration is empty, so **the promotion gate currently fails closed**.
- No result, TIFF, organizer score, or leaderboard improvement is claimed. See [`preregistration.json`](preregistration.json), [`preregistration_revisions.md`](preregistration_revisions.md), and the [source/irregularity register](sources.md).
